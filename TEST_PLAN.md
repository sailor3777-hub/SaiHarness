# Ручное тестирование SaiHarness

Отмечай `[x]` по ходу. Рядом с шагом написано, что должно получиться. Если результат другой, смотри раздел «Если что-то не так» в конце.

## 0. Подготовка

1. Закрой приложение и сохрани копию данных (тесты меняют чаты, папки, права):

```powershell
Copy-Item data data_backup -Recurse
```

2. Создай тестовые папки `Alpha` и `Beta` (скрипт можно запускать повторно, он возвращает файлы в исходное состояние и удаляет `.bak`):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make_test_sandbox.ps1
```

| Файл | Зачем |
|---|---|
| `Alpha\readme.md` | обычный текст, внутри «ФИОЛЕТОВЫЙ-МАМОНТ-42» |
| `Alpha\sub\code.py` | подпапка |
| `Alpha\cp1251.txt`, `Alpha\bom.txt`, `Alpha\crlf.txt` | кодировки и переводы строк |
| `Alpha\big.txt` | 750 КБ: больше лимита 300 КБ |
| `Alpha\image.png` | бинарный |
| `Alpha\.git\config` | служебная папка, в контекст попадать не должна |
| `Beta\requirements.txt` | «yellow sausage» на 3-й строке, переводы строк CRLF |
| `Beta\dup.txt` | «яблоко и яблоко» (фрагмент встречается дважды) |
| `Beta\notes.txt` | обычная заметка |

3. Запусти LM Studio, загрузи одну модель с `tool_use` (например gemma-4-e4b) и включи сервер на порту 1234.
4. Запусти приложение:

```powershell
.venv\Scripts\python app.py
```

- [ ] **H1** После перезапуска сохраняются: чаты и история, подключения, профили, корни во вкладке «Файлы», выбор файлов и инструментов по чатам, права инструментов.

- [ ] **H3** В `data\crash.log` записи привязаны к номеру процесса: `=== start … pid=N` и `=== exit … pid=N`. Старые записи без `pid` (до 15.10) парой не считаются. Если какой-то запуск оборвался, при следующем старте появится `=== lost … pid=N (запуск … не завершился штатно)`: это аварийное завершение, пришли мне строки рядом. Запущенное прямо сейчас приложение без `exit` нормально, как и параллельные экземпляры. Перед каждым запросом к модели в этот же файл пишется строка `[req] … запрос≈N ток. лимит=L rss=… ram_свободно=…`: если приложение закроется молча, последняя такая строка покажет, какого размера был запрос и сколько оставалось памяти.

## Что не считать ошибкой

- Небольшие модели иногда зовут инструмент не тем путём, забывают аргумент или отвечают без вызова. Смотри строки `▸`/`◂` в чате: если они верные, а пересказ модели нет, это поведение модели.
- Время ответа зависит от железа, а не от схемы.
- Оценка токенов приблизительная: на тексте ошибается в среднем на 5%, на коде может занижать до 20%. Поэтому защита от переполнения берёт запас (+15%) и отказывает чуть раньше, чем контекст заполнится на самом деле. Точное число сервер присылает после ответа.
- PDF, Word, Excel и картинки не читаются. UTF-16 читается, но не правится.
- Рядом с изменёнными файлами копятся `.bak`.
- Результаты инструментов остаются в истории чата и занимают контекст (строка «Запрос целиком» это показывает).
- Предел: один результат инструмента до 12 000 символов, вызов до 60 секунд, до 16 раундов инструментов за один ответ. Когда лимит исчерпан, модель просят подвести итог без инструментов, и в чате видно предупреждение «Достигнут предел шагов». Если нужна многошаговая задача (например, правка нескольких файлов), давай её по одному файлу.
- Неуникальный фрагмент в `fs_replace`: модель сама должна расширить фрагмент. Не у каждой модели получается, это не ошибка обвязки.
- Корни во вкладке «Файлы» добавляются и убираются целиком. Подпапку корня отдельно не убрать, зато в дереве можно снять галочку с любой подпапки.

## Если что-то не так

Пришли:

1. Номер шага и что ожидалось против того, что получилось.
2. Скриншот или текст чата (теперь в нём остаются строки «Система» с ошибками).
3. Содержимое окна «Запрос» для этого чата.
4. Последние строки `data\crash.log` и, если речь об инструментах, `data\logs\mcp-toolbox.log`.

После тестов можно вернуть данные из копии (`data_backup`) и удалить папку `test_sandbox`.
