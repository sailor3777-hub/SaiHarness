# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

SaiHarness is a PySide6 desktop harness for local LLMs served by LM Studio (OpenAI-compatible API, default `localhost:1234`). Python 3.14, venv in `.venv`, deps in `requirements.txt` (httpx, markdown-it-py, mcp, PySide6). This is the English version: UI text, model prompts, tool descriptions, comments, tests and docs are in English. The user writes to Claude in Russian; answer in Russian. Git repo: private `https://github.com/sailor3777-hub/SaiHarness`; this English version is the branch `en`, the Russian version is `main` (the two are not kept in sync automatically). `data/`, `data_backup/`, `.venv/`, `test_sandbox/`, `.env` are in `.gitignore`. Workflow: after a finished change, show the diff and a proposed commit message, commit and push only after the user confirms.

## Commands

```powershell
Run.cmd                                                                  # installer/launcher: finds Python, creates .venv, installs missing deps from requirements.txt, starts the app
Install.cmd                                                              # same, without starting the app (Run.cmd --check only reports what is missing)
.venv\Scripts\python app.py                                              # run the app directly
powershell -ExecutionPolicy Bypass -File tests\run_all.ps1               # offline suite (offscreen Qt, no LM Studio)
powershell -ExecutionPolicy Bypass -File tests\run_all.ps1 -Gui          # + window tests on the real Qt platform
powershell -ExecutionPolicy Bypass -File tests\run_all.ps1 -Live         # + tests against a running LM Studio
powershell -ExecutionPolicy Bypass -File scripts\make_test_sandbox.ps1   # recreate test_sandbox\Alpha, Beta for manual testing (TEST_PLAN.md)
```

There is no pytest/linter. Each `tests/test_*.py` is a standalone script that prints `OK`/`FAIL` lines and `ALL OK`; `run_all.ps1` greps for those. The suite lists are hardcoded in `run_all.ps1` — a new test file must be added there. To run a single test (from the project folder):

```powershell
$env:QT_QPA_PLATFORM='offscreen'; $env:PYTHONPATH=(Get-Location).Path; .venv\Scripts\python tests\test_richtext.py $env:TEMP\sai_x.db
```

Tests take a temp DB path as `argv[1]` and set `db.DB_PATH` to it; they must never touch `data\saiharness.db`. Delete the temp DB before re-running a single test by hand (`run_all.ps1` does it): some tests assume an empty database. Tests that start a subprocess or read project files use the folder of the test itself (`ROOT = Path(__file__).resolve().parents[1]`), never a hardcoded copy. Live tests (`tests/test_live_chat.py`, `live_scenario_*.py`) only use models already loaded in LM Studio — never load/unload models or disturb other processes there without the user's permission.

## Architecture

- `app.py` installs `core.diag` (writes `data/crash.log` with faulthandler traces, `=== start/exit/lost pid=N` markers, `[req]` memory lines), applies `ui/theme.qss`, opens `ui.main_window.MainWindow`.
- Installer: `Run.cmd` (ASCII and CRLF only: after `chcp 65001` cmd mis-parses UTF-8 in .cmd files; do not call commands from the current folder without a path inside it, `NoDefaultCurrentDirectoryInExePath` may be on) finds an interpreter (`.venv`, then `py -3`, `python`; with no Python 3.11+ it offers `winget install Python.Python.3.14`) and calls `scripts/bootstrap.py` (pure stdlib, tests in `tests/test_bootstrap.py`). It creates `.venv`, compares installed versions with the ones pinned in `requirements.txt` (one interpreter run, the fast path takes ≈0.4 s), runs `pip install -r` on a mismatch, then starts `pythonw app.py` as a separate process. A new dependency = a `name==version` line in `requirements.txt`; it is pulled in on the next start.
- Themes: `ui/themes.py` (three themes: dark = `ui/theme.qss`, light `theme_light.qss`, Diablo `theme_diablo.qss`; `Theme` also holds the colors the code sets itself: labels and reasoning in the chat HTML, tree rows, code style). `themes.apply(key)` sets the QSS, saves the key in `app_settings` (`theme`) and emits `themes.bus.changed`: the chat is redrawn, the Files and Tools panels are rebuilt. The selector (`QComboBox`) sits in `ChatList` above "+ New chat". Take a new color in code from `themes.current()`, not a constant.
- `ui/` — main window: chats list on the left, dialog in the center, right-hand tabs (Files / Tools / Web / Memory / Model, plus Connection / Model Builder). `main_window.py` wires panels to the DB and worker.
- `worker.py` — all background work. `AsyncCall` runs a function in a thread with a watchdog timeout (a new `start()` invalidates the previous result). `ChatStreamer` (QThread) is the agent loop: build request → check it fits the loaded model's context → stream via `core/llm.py` → execute tool calls through `ToolRouter` → repeat up to the profile's `max_steps`, then force a text summary without tools.
- `core/db.py` — SQLite (`data/saiharness.db`; `DB_PATH` is monkey-patched by tests): chats, messages, connections, model profiles, roots, per-chat file/tool selections.
- `core/context_builder.py` — builds messages (profile system prompt, memory, attached files) and the token estimator. The estimator is calibrated against Qwen/Gemma measurements (`tests/tools/token_*.py`, `tests/data`); the pre-request guard requires request + reply reserve ≤ loaded context with a 15% safety margin (`CONTEXT_SAFETY` in `worker.py`). Don't loosen the correction factor below ×1.0. The calibration data in `tests/data/tokdata_qwen4b.json` was collected on the Russian version (mostly Cyrillic text); the per-class coefficients (`_TOKENS_PER_CHAR` in `core/files.py`) do not depend on the language, but re-collect samples with `tests/tools/token_tokdata.py` on a loaded model and refit with `token_tokfit.py` when there is a chance.
- Text markers: `core/markers.py` (no Qt) holds the strings the code reads meaning from — `ERROR_WORD`/`ERROR_PREFIX` ("ERROR: ", with `error()` and `is_error()`), `NOT_FOUND` (the "file not found" skip reason shared by `core.files`, `core.docs` and `fs_read`). `core.imagegen.RESULT_PREFIX` (the chat finds a generated picture by it) and `core.db.DEFAULT_CHAT_TITLE` (a chat is auto-titled only while it has it, `db.is_default_title`) live in their modules. Each has a `LEGACY_*` tuple with the Russian version's wording, because old databases keep chats and tool results in Russian: extend it, never just replace a wording.
- Tools: `core/mcp_manager.py` runs MCP servers from `data/mcp.json` on its own asyncio loop. The built-in server is `tools_server.py` (toolbox: calc, time_now, fs_roots/list/read/search/replace, notes_write → `data/notes`, and the tools below). The model never sees raw tool schemas: `core/tools.py` exposes only three meta-tools (`find_tool`, `describe_tool`, `call_tool` with a `tool` param) plus a compact catalog; `ToolRouter` validates arguments and enforces permissions. `Catalog.find` matches query words with tool names and descriptions by a shared part of 4+ characters; descriptions are English, so a Russian query finds nothing and the router falls back to listing all tools.
- Tool errors: a tool in `tools_server.py` returns `ERROR_PREFIX + text`; the `@tool` decorator turns that into an MCP result with `is_error=True` and the text without the prefix (the function itself stays undecorated for direct calls). `ToolRouter` counts errors by that flag and adds the prefix back for the model, so a file whose content starts with "ERROR" is never mistaken for an error. Tool tests use `tests/model_view.py` (`McpManager` that adds the prefix the way the router does).
- Shell: `shell_run(command, cwd)` in `tools_server.py` (logic in `core/shell.py`, no Qt) runs PowerShell through `-EncodedCommand`, cwd is any folder (access to the whole system by the user's decision; without `cwd` the first allowed root, and without roots the service folder `data/shell`), streams are merged into stdout inside PowerShell (otherwise with `-EncodedCommand` stderr arrives as CLIXML), 60 s timeout with killing the process tree (the router's `TOOL_TIMEOUTS` gives it 90 s). Every call asks, there is no allow list; the window shows the whole command. Output ≤ `MAX_READ_CHARS`, the rest is read by the read-only `shell_output(run_id, offset)` from the server's memory (the last 20 runs), the command is not run again. This also covers creating new files by the model.
- Office: `docx_write(path, markdown, overwrite)` and `xlsx_write(path, sheets, overwrite)` (logic in `core/office.py`, no Qt; python-docx, openpyxl, markdown-it-py) create Word from Markdown (headings, nested lists, tables, quotes, code) and Excel from `{sheet: [[cells]]}` (a string starting with "=" is written as a formula). An existing file is not overwritten without `overwrite=true`, then the old one goes to `.bak`; writing is atomic; a relative path starts from the first allowed folder. PDF and pptx are deliberately not made (PDF from Word by hand, presentations with a cloud model).
- Permissions follow MCP annotations: read-only tools run without asking; write tools (`fs_replace`, `notes_write`, …) show a confirmation dialog (`ui/permission.py`: File / Was / Will be). `fs_replace` requires exactly one match, writes a `.bak`, and preserves encoding and CRLF.
- File selection and tool enablement are stored per chat (new chats start with tools off); root folders are shared across chats.
- Web: `core/web/` (pure Python, no Qt) — `safety.py` (SSRF: only public http/https addresses, checked on every redirect), `fetch.py` (httpx, 2 MB limit, robots.txt and a pause in crawl mode, cache in `data/web_cache`), `extract.py` (HTML → text on `html.parser`), `paginate.py` (a long page is given in chunks through `offset`; a chunk ≤ 10,500 characters, because the router cuts a tool result to `MAX_RESULT_CHARS` = 12,000), `index.py` (SQLite FTS5/BM25 in the main database: `web_sources`, `web_pages`, `web_fts`; the crawler). `tools_server.py` provides `web_search` (over the local index, read-only) and `web_extract` (goes online, so it asks by default). JS pages are rendered by `web_render.py` (Qt WebEngine) as a separate process: `core/web/render.py` starts it from `tools_server.py` and the crawler. The index is filled on the Web tab (`ui/web_panel.py`, crawling in `worker.CrawlThread`). `web_search_internet` searches through the user's own SearXNG (`core/web/searxng.py`; the address is stored in the `web_settings` table and set on the Web tab; the private-address protection does not apply to it, it is the user's own server). `SAI_WEB_ALLOW_PRIVATE=1` and `SAI_WEB_DELAY` are only for tests with a local server.
- Answer in the reasoning: Qwen 3.5 in LM Studio sometimes returns the whole answer as `reasoning_content` with empty `content`. In that case `main_window._finish` (`llm.answer_in_reasoning`: the stream ended normally, no error or stop, the answer was not cut off by the token limit) saves the reasoning as a normal answer so that it is visible and stays in the model's history. Reasoning cut off by the limit does not count as an answer.
- Documents: `core/docs.py` (no Qt; pypdf, python-docx, openpyxl) gives the text of PDF / .docx / .xlsx(.xlsm) to `fs_read`: PDF pages with "--- page N of M ---" markers, Word headings as `#` (style names are matched in English and Russian — "Heading"/"Заголовок", "List"/"Список" — because files from a Russian Word keep localized names; keep both), tables as rows joined with " | ", Excel sheets with tabs (formulas as the last saved value). A scan without a text layer and a password-protected PDF give a clear error. `fs_read` reads a chunk ≤ `MAX_READ_CHARS` = 10,500 characters (the router cuts the result to 12,000) and accepts `offset`; the end of a truncated chunk says which offset to read from next. On the Files tab (`load_context`) explicitly checked documents go into the context as the same text (cache `docs.read_document_cached` by path, modification time and size; text longer than `MAX_FILE_BYTES` and scans are skipped with a reason); a checked folder does not pull in documents by itself.
- Encodings: `core/files.py` decodes non-UTF-8 text as cp1251 (the usual encoding of the user's old Russian files) and `fs_replace` writes it back in cp1251; this is deliberate, keep it.
- Repeated errors: `ToolRouter` remembers which error a tool returned in a row (by the first 160 characters of the text). On the second identical error "do not repeat it, tell the user" is added to the result; on the third call the tool is not run at all (`REPEAT_ERROR_BLOCK`); a success or a different error resets the count. The router is created for every reply, so the count starts again with every message. A blocked call sets `router.stuck`; then `ChatStreamer._loop` does not wait for the step limit but disables tools at once and asks the model to sum up (`STUCK_NUDGE`, like `LIMIT_NUDGE`; this request does not go into the chat history). This is against model loops (a 9b model called an unconfigured `vision_describe` 16 times over 6 minutes).
- Long-term memory: `core/memory.py` (no Qt) — the `memories` table (topic, title, text) and an FTS5 index in the main database, shared by all profiles and chats. FTS5 has no morphology, so the index holds "stems": Latin words lose simple English endings (-s, -es, -ies, -ed, -ing, a final e, a doubled consonant) and are cut to `LATIN_STEM_LEN` = 6 letters; Cyrillic words (entries from the Russian version) are cut to `STEM_LEN` = 4 letters, with ё = е. A query searches by stem prefix; topics and titles are compared with `key()`, because SQLite `NOCASE` does not handle non-Latin case. The stem rules have a version (`INDEX_VERSION` in the `memory_meta` table): when it changes, `ensure_schema` recomputes the `i_*` columns from the stored text once (the entries and `updated_at` are not touched). Tools in `tools_server.py`: `memory_save` (asks; the same topic and title update the entry), `memory_search`, `memory_topics`, `memory_read` (read-only), `memory_delete` (asks). The agent's behavior is set by the profile field "Memory rules" (`model_profiles.memory_rules`, empty = `core.memory.DEFAULT_RULES`; the editor shows the default text, an unchanged one is not copied into the database; profiles saved by the Russian version may hold Russian rules and system prompts — that is user data, leave it). `memory.prompt_block` (called by `MainWindow._tools_text`) adds the rules and the line "Topics in memory: …" to the tool catalog only if `memory_save` or `memory_search` is enabled. `core.tools.REQUIRES` is the tool dependency map (enabling pulls in the required ones, applied in `ToolsPanel.enabled_tools` and `_sync`); empty for now. The Memory tab (`ui/memory_panel.py`): a list with a topic filter and search (the same `Memory.search`), an editor for topic / title / text, "New entry", deleting with confirmation; it re-reads the database every time the tab is shown (the model writes entries from another process), unsaved text in the editor is not overwritten on re-reading. Not done: automatic retrieval without a model call, indexing files into the same stack.
- Vision: `vision_describe(path, question)` in `tools_server.py` (logic in `core/vision.py`, no Qt) sends a picture from the allowed folders in one plain `/chat/completions` request to LM Studio using the vision profile chosen on the Tools tab (the `vision_profile` setting in `app_settings`). The profile's connection, model, temperature and max_tokens are used, but not its system prompt (the vision model gets its own one and answers in English). The agent loop is not involved, so models without vision call it like any other tool.
- Image generation: `image_generate(prompt, width, height, steps)` in `tools_server.py` (logic in `core/imagegen.py`, no Qt) drives the user's ComfyUI: a workflow in API format (`data/comfy_workflow.json`, Save (API Format); `SAI_COMFY_WORKFLOW` overrides the path), the server address is the `comfy_url` setting in `app_settings` (a field on the Tools tab). Nodes are found by type and links (the CLIPTextEncode under the KSampler's positive input, an empty latent with width/height, seed and steps in the KSampler), there is no manual mapping. The model sets the size (200×200 stays 200×200): from 64, a multiple of 8 (rounded down), ≤1536 per side and ≤1 megapixel; the seed is random. `POST /prompt` → polling `/history/<id>` → `/view` → a file in `data/images` (`SAI_IMAGES_DIR` for tests). It asks for confirmation, the call timeout is 960 s. A live run: Z-Image Turbo on a GTX 1650, 512×512 takes ≥5 min and is not faster after loading (the user starts ComfyUI by hand and draws rarely, "for fun"; the GPU is shared with LM Studio). In the chat `ChatView._tool_result_html` shows the picture itself under the result (width 320) by `imagegen.result_path`.
- Pictures in the chat: the 📎 button, Ctrl+V and drag and drop into the input field (`ui/chat_view.py`); files are copied to `data/images` (long side ≤ 1280), paths are stored in `messages.images` (JSON). `core/images.py` (no Qt): in the request a picture is first a "placeholder" `sai-image:path` (the token estimate and the Request window do not read files), and `main_window._image_preparer` in the reply thread replaces it with a data URL if the chat model's `llm.model_type` is `vlm` (or unknown), otherwise with a description from the vision model (`vision.describe_cached`, cache `<file>.txt`). Pictures older than the last `HISTORY_IMAGE_MESSAGES` messages are not sent to the model (a note stays). A picture counts as `IMAGE_TOKENS` in the token estimate, then the server's usage corrects it.
- `core/richtext.py` converts LaTeX-ish fragments to Unicode and renders Markdown to safe HTML (raw HTML is escaped).

## What stays in Russian on purpose

Check with a Cyrillic search after changes; only these should remain:

- `LEGACY_*` tuples in `core/markers.py`, `core/imagegen.py`, `core/db.py` (old databases).
- `core/docs.py` Word style names "Заголовок" / "Список"; `core/memory.py` ё → е.
- Test data that checks Russian behavior: cp1251 / UTF-16 / BOM files (`test_files_core.py`, `test_fs_replace.py`, `scripts/make_test_sandbox.ps1`), Russian memory stems and the reindex test (`test_memory.py`), the measured token samples (`test_token_estimator.py`, `tests/tools/token_tokcal.py`, `token_tokdata.py`, `tests/data/tokdata_qwen4b.json`), a Russian Word style (`test_docs.py`), the Russian legacy image result (`test_imagegen.py`), the Cyrillic token class (`test_files_core.py`).

## Conventions worth knowing

- Don't add a "show earlier messages" button for long chats — the user explicitly dislikes it.
- Models run on different hardware (gemma on an MSI Claw, qwen on a GTX 1650), so don't compare response times across models.
- `TEST_PLAN.md` is the manual checklist; back up `data\` (`data_backup\`) before manual runs since they change chats and permissions.
