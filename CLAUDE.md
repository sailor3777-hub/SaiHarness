# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

SaiHarness is a PySide6 desktop harness for local LLMs served by LM Studio (OpenAI-compatible API, default `localhost:1234`). Python 3.14, venv in `.venv`, deps in `requirements.txt` (httpx, markdown-it-py, mcp, PySide6). The UI text, comments, and the user's chat language are Russian. Git repo: private `https://github.com/sailor3777-hub/SaiHarness` (branch `main`); `data/`, `data_backup/`, `.venv/`, `test_sandbox/`, `.env` are in `.gitignore`. Workflow: after a finished change, show the diff and a proposed commit message, commit and push only after the user confirms.

## Commands

```powershell
Run.cmd                                                                  # installer/launcher: finds Python, creates .venv, installs missing deps from requirements.txt, starts the app
Install.cmd                                                              # same, without starting the app (Run.cmd --check only reports what is missing)
.venv\Scripts\python app.py                                              # run the app directly
powershell -ExecutionPolicy Bypass -File tests\run_all.ps1               # offline suite (offscreen Qt, no LM Studio)
powershell -ExecutionPolicy Bypass -File tests\run_all.ps1 -Gui          # + window tests on the real Qt platform
powershell -ExecutionPolicy Bypass -File tests\run_all.ps1 -Live         # + tests against a running LM Studio
powershell -ExecutionPolicy Bypass -File scripts\make_test_sandbox.ps1   # recreate test_sandbox\Alpha, Beta for manual testing (TEST_PLAN.md)
```

There is no pytest/linter. Each `tests/test_*.py` is a standalone script that prints `OK`/`FAIL` lines and `ALL OK`; `run_all.ps1` greps for those. The suite lists are hardcoded in `run_all.ps1` — a new test file must be added there. To run a single test:

```powershell
$env:QT_QPA_PLATFORM='offscreen'; $env:PYTHONPATH='C:\SaiHarness'; .venv\Scripts\python tests\test_richtext.py $env:TEMP\sai_x.db
```

Tests take a temp DB path as `argv[1]` and set `db.DB_PATH` to it; they must never touch `data\saiharness.db`. Live tests (`tests/test_live_chat.py`, `live_scenario_*.py`) only use models already loaded in LM Studio — never load/unload models or disturb other processes there without the user's permission.

## Architecture

- `app.py` installs `core.diag` (writes `data/crash.log` with faulthandler traces, `=== start/exit/lost pid=N` markers, `[req]` memory lines), applies `ui/theme.qss`, opens `ui.main_window.MainWindow`.
- Установщик: `Run.cmd` (только ASCII и CRLF: после `chcp 65001` cmd путает UTF-8 в .cmd; внутри не звать команды из текущей папки без пути, `NoDefaultCurrentDirectoryInExePath` может быть включён) ищет интерпретатор (`.venv`, затем `py -3`, `python`; нет Python 3.11+ — предлагает `winget install Python.Python.3.14`) и вызывает `scripts/bootstrap.py` (чистый stdlib, тесты в `tests/test_bootstrap.py`). Он создаёт `.venv`, сверяет установленные версии с закреплёнными в `requirements.txt` (один запуск интерпретатора, быстрый путь ≈0,4 с), при расхождении делает `pip install -r`, затем запускает `pythonw app.py` отдельным процессом. Новая зависимость = строка `имя==версия` в `requirements.txt`, при следующем запуске она подтянется сама.
- Темы: `ui/themes.py` (три темы: тёмная = `ui/theme.qss`, светлая `theme_light.qss`, Diablo `theme_diablo.qss`; в `Theme` ещё цвета, которые код задаёт сам: подписи и размышления в HTML чата, строки деревьев, стиль кода). `themes.apply(key)` ставит QSS, сохраняет ключ в `app_settings` (`theme`) и шлёт `themes.bus.changed`: чат перерисовывается, панели «Файлы» и «Инструменты» перестраиваются. Селектор (`QComboBox`) стоит в `ChatList` над «+ Новый чат». Новый цвет в коде брать из `themes.current()`, а не константой.
- `ui/` — main window: chats list on the left, dialog in the center, right-hand tabs (Files / Tools / Model / Connection / Model Builder). `main_window.py` wires panels to the DB and worker.
- `worker.py` — all background work. `AsyncCall` runs a function in a thread with a watchdog timeout (a new `start()` invalidates the previous result). `ChatStreamer` (QThread) is the agent loop: build request → check it fits the loaded model's context → stream via `core/llm.py` → execute tool calls through `ToolRouter` → repeat up to the profile's `max_steps`, then force a text summary without tools.
- `core/db.py` — SQLite (`data/saiharness.db`; `DB_PATH` is monkey-patched by tests): chats, messages, connections, model profiles, roots, per-chat file/tool selections.
- `core/context_builder.py` — builds messages (profile system prompt, memory, attached files) and the token estimator. The estimator is calibrated against Qwen/Gemma measurements (`tests/tools/token_*.py`, `tests/data`); the pre-request guard requires request + reply reserve ≤ loaded context with a 15% safety margin (`CONTEXT_SAFETY` in `worker.py`). Don't loosen the correction factor below ×1.0.
- Tools: `core/mcp_manager.py` runs MCP servers from `data/mcp.json` on its own asyncio loop. The built-in server is `tools_server.py` (toolbox: calc, time_now, fs_roots/list/read/search/replace, notes_write → `data/notes`). The model never sees raw tool schemas: `core/tools.py` exposes only three meta-tools (`find_tool`, `describe_tool`, `call_tool` with a `tool` param) plus a compact catalog; `ToolRouter` validates arguments and enforces permissions.
- Shell: `shell_run(command, cwd)` в `tools_server.py` (логика в `core/shell.py`, без Qt) запускает PowerShell через `-EncodedCommand`, cwd любая папка (доступ ко всей системе по решению пользователя; без `cwd` берётся первый разрешённый корень, а без корней служебная `data/shell`), потоки сливаются в stdout внутри PowerShell (иначе при `-EncodedCommand` stderr приходит как CLIXML), таймаут 60 с с убийством дерева процессов (у роутера для него `TOOL_TIMEOUTS` = 90 с). Каждый вызов спрашивает, белого списка нет; окно показывает команду целиком. Вывод ≤ `MAX_READ_CHARS`, остаток читает read-only `shell_output(run_id, offset)` из памяти сервера (последние 20 запусков), команда заново не запускается. Это же закрывает создание новых файлов моделью.
- Office: `docx_write(path, markdown, overwrite)` и `xlsx_write(path, sheets, overwrite)` (логика в `core/office.py`, без Qt; python-docx, openpyxl, markdown-it-py) создают Word из Markdown (заголовки, списки с вложенностью, таблицы, цитаты, код) и Excel из `{лист: [[ячейки]]}` (строка с «=» пишется формулой). Существующий файл не затирается без `overwrite=true`, тогда старый уходит в `.bak`; запись атомарная; относительный путь считается от первой разрешённой папки. PDF и pptx сознательно не делаем (PDF из Word вручную, презентации облачной моделью).
- Permissions follow MCP annotations: read-only tools run without asking; write tools (`fs_replace`, `notes_write`) show a confirmation dialog (`ui/permission.py`: file / was / will be). `fs_replace` requires exactly one match, writes a `.bak`, and preserves encoding and CRLF.
- File selection and tool enablement are stored per chat (new chats start with tools off); root folders are shared across chats.
- Web: `core/web/` (чистый Python, без Qt) — `safety.py` (SSRF: только публичные http/https-адреса, проверка на каждом редиректе), `fetch.py` (httpx, лимит 2 МБ, robots.txt и пауза в режиме обхода, кэш в `data/web_cache`), `extract.py` (HTML → текст на `html.parser`), `paginate.py` (длинная страница отдаётся кусками через `offset`; кусок ≤ 10 500 символов, потому что роутер режет результат инструмента до `MAX_RESULT_CHARS` = 12 000), `index.py` (SQLite FTS5/BM25 в основной базе: `web_sources`, `web_pages`, `web_fts`; краулер). `tools_server.py` даёт `web_search` (по локальному индексу, read-only) и `web_extract` (выход в сеть, поэтому по умолчанию спрашивает). JS-страницы рисует `web_render.py` (Qt WebEngine) отдельным процессом: `core/web/render.py` запускает его из `tools_server.py` и краулера. Индекс наполняет вкладка «Веб» (`ui/web_panel.py`, обход в `worker.CrawlThread`). `web_search_internet` ищет через собственный SearXNG пользователя (`core/web/searxng.py`; адрес хранится в таблице `web_settings` и задаётся во вкладке «Веб»; на этот адрес защита от частных адресов не действует, это сервер самого пользователя). `SAI_WEB_ALLOW_PRIVATE=1` и `SAI_WEB_DELAY` нужны только тестам с локальным сервером.
- Ответ в размышлениях: Qwen 3.5 в LM Studio иногда отдаёт весь ответ как `reasoning_content` при пустом `content`. `main_window._finish` в таком случае (`llm.answer_in_reasoning`: поток завершён нормально, нет ошибки и остановки, ответ не оборван лимитом токенов) сохраняет размышления как обычный ответ, чтобы он был виден и остался в истории модели. Размышления, оборванные лимитом, ответом не считаются.
- Документы: `core/docs.py` (без Qt; pypdf, python-docx, openpyxl) отдаёт текст PDF / .docx / .xlsx(.xlsm) для `fs_read`: страницы PDF с маркерами «--- стр. N ---», заголовки Word как `#`, таблицы строками через « | », листы Excel через табуляцию (формулы — последним сохранённым значением). Скан без текстового слоя и PDF с паролем дают понятную ошибку. `fs_read` читает куском ≤ `MAX_READ_CHARS` = 10 500 символов (роутер режет результат на 12 000) и принимает `offset`; в конце усечённого куска написано, с какого offset читать дальше. Во вкладке «Файлы» (`load_context`) явно отмеченные документы идут в контекст тем же текстом (кеш `docs.read_document_cached` по пути, времени изменения и размеру; текст длиннее `MAX_FILE_BYTES` и сканы пропускаются с причиной); папка с галочкой документы сама не тянет.
- Повторы ошибок: `ToolRouter` помнит, какую ошибку инструмент вернул подряд (по первым 160 символам текста). На второй такой же ошибке к результату добавляется «не повторяй, скажи пользователю», на третий вызов инструмент не выполняется вовсе (`REPEAT_ERROR_BLOCK`); успех или другая ошибка сбрасывают счёт. Роутер создаётся на каждый ответ, так что счёт начинается заново с каждым сообщением. Заблокированный вызов ставит `router.stuck`; тогда `ChatStreamer._loop` не ждёт лимита шагов, а сразу отключает инструменты и просит модель подвести итог (`STUCK_NUDGE`, как с `LIMIT_NUDGE`, в историю чата эта просьба не попадает). Это нужно против зацикливания модели (9b вызвала не настроенный `vision_describe` 16 раз и 6 минут).
- Долгосрочная память: `core/memory.py` (без Qt) — таблица `memories` (тема, заголовок, текст) и FTS5-индекс в основной базе, общая для всех профилей и чатов. FTS5 не знает морфологии, поэтому в индекс идут «основы» (слова обрезаны до `STEM_LEN` = 4 букв, запрос ищет по префиксу основы; регистр тем и заголовков сравнивается через `key()`, потому что SQLite `NOCASE` кириллицу не понимает). Инструменты в `tools_server.py`: `memory_save` (спрашивает; та же тема и заголовок обновляют запись), `memory_search`, `memory_topics`, `memory_read` (read-only), `memory_delete` (спрашивает). Поведение агента задаёт поле профиля «Правила памяти» (`model_profiles.memory_rules`, пусто = `core.memory.DEFAULT_RULES`; в редакторе показан текст по умолчанию, неизменённый не копируется в базу). `memory.prompt_block` (его зовёт `MainWindow._tools_text`) добавляет к каталогу инструментов правила и строку «Темы в памяти: …», только если включён `memory_save` или `memory_search`. `core.tools.REQUIRES` — карта зависимостей инструментов (включение тянет требуемые, применяется в `ToolsPanel.enabled_tools` и `_sync`); пока пуста. Вкладка «Память» (`ui/memory_panel.py`): список с фильтром по теме и поиском (тот же `Memory.search`), редактор темы / заголовка / текста, «Новая запись», удаление с подтверждением; при каждом показе вкладки читает базу заново (записи пишет модель из другого процесса), несохранённый текст в редакторе при перечитывании не затирается. Не сделано: автоподстановка найденного без вызова модели, индексация файлов в тот же стек.
- Vision: `vision_describe(path, question)` в `tools_server.py` (логика в `core/vision.py`, без Qt) шлёт картинку из разрешённых папок одним обычным запросом `/chat/completions` в LM Studio на vision-профиль, выбранный во вкладке «Инструменты» (настройка `vision_profile` в таблице `app_settings`). Берутся подключение, модель, температура и max_tokens профиля, но не его системный промпт. Агентский цикл не задействуется, поэтому модели без зрения вызывают его как обычный инструмент.
- Генерация картинок: `image_generate(prompt, width, height, steps)` в `tools_server.py` (логика в `core/imagegen.py`, без Qt) гоняет ComfyUI пользователя: workflow в API-формате (`data/comfy_workflow.json`, Save (API Format); путь переопределяет `SAI_COMFY_WORKFLOW`), адрес сервера — настройка `comfy_url` в `app_settings` (поле во вкладке «Инструменты»). Узлы ищутся сами по типу и связям (CLIPTextEncode под positive у KSampler, пустой латент с width/height, seed и шаги в KSampler), ручного сопоставления нет. Размер задаёт модель (200×200 остаётся 200×200): от 64, кратен 8 (округление вниз), ≤1536 по стороне и ≤1 Мпикс; seed случайный. `POST /prompt` → опрос `/history/<id>` → `/view` → файл в `data/images` (`SAI_IMAGES_DIR` для тестов). Спрашивает подтверждение, таймаут вызова 960 с. Живой прогон: Z-Image Turbo на GTX 1650, 512×512 ≥5 мин и после загрузки не быстрее (пользователь стартует ComfyUI вручную и рисует редко, «для прикола»; видеокарта общая с LM Studio). В чате `ChatView._tool_result_html` по префиксу `imagegen.RESULT_PREFIX` показывает под результатом саму картинку (ширина 320).
- Картинки в чате: кнопка 📎, Ctrl+V и перетаскивание в поле ввода (`ui/chat_view.py`); файлы копируются в `data/images` (длинная сторона ≤ 1280), пути лежат в `messages.images` (JSON). `core/images.py` (без Qt): в запросе картинка сначала «заглушка» `sai-image:путь` (оценка токенов и окно «Запрос» не читают файлы), а `main_window._image_preparer` в потоке ответа заменяет её на data-URL, если `llm.model_type` модели чата `vlm` (или неизвестен), иначе на описание от vision-модели (`vision.describe_cached`, кеш `<файл>.txt`). Картинки старше `HISTORY_IMAGE_MESSAGES` последних сообщений модели не отправляются (остаётся пометка). Картинка в оценке токенов = `IMAGE_TOKENS`, дальше поправка по usage сервера.
- `core/richtext.py` converts LaTeX-ish fragments to Unicode and renders Markdown to safe HTML (raw HTML is escaped).

## Conventions worth knowing

- Don't add a "show earlier messages" button for long chats — the user explicitly dislikes it.
- Models run on different hardware (gemma on an MSI Claw, qwen on a GTX 1650), so don't compare response times across models.
- `TEST_PLAN.md` is the manual checklist; back up `data\` (`data_backup\`) before manual runs since they change chats and permissions.
